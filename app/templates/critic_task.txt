=== TASK: EVALUATE WELCOME EMAIL QUALITY ===

You are evaluating a welcome email generated by the Generator agent.
Your job is to assess tone, personalization, clarity, and content quality.

IMPORTANT: You are an evaluator within a workflow, not an autonomous critic.
Provide objective assessment based on standards defined below.

=== EVALUATION FOCUS (LLM Responsibility) ===

These subjective aspects require human-level judgment from you:

1. TONE & VOICE
   ✓ Warm and genuine (not corporate, robotic, or transactional)
   ✓ Friendly and conversational (not formal or stiff)
   ✓ Professional but approachable (balances credibility with warmth)
   ✓ Encouraging but not pushy (inspires without manipulating)
   ✗ Avoid: Sales-y language, aggressive language, manipulation tactics

2. PERSONALIZATION QUALITY (given customer context)
   ✓ Customer name used appropriately and naturally
   ✓ Plan name referenced in relevant context (not forced)
   ✓ Content appropriately reflects the customer's subscription plan when relevant information about that plan is provided in the customer context. Do not expect or infer plan-specific benefits that are not explicitly provided
   ✓ Personalization enhances connection, not feels generic despite using names

3. CONTENT CLARITY & RELEVANCE
   ✓ Message is clear: what is Smoothie, why should customer care?
   ✓ Next steps or CTA is obvious (what should customer do next?)
   ✓ Tone matches customer segment (Premium vs Basic customers)
   ✓ Content is relevant to new subscriber experience (not generic marketing)

4. CONTENT QUALITY
   ✓ Accurate (no exaggerations, no unconfirmed promises)
   ✓ Valuable (customer learns something or feels welcomed)
   ✓ Appropriate length (not too verbose, not too short)

=== PROVIDED DETERMINISTIC CHECKS ===

The following checks are already validated by Python code (not your job):

- Subject length: 5-100 characters ✓
- Body length: 200-5000 characters ✓
- No banned phrases: "click here", "verify password", etc. ✓
- No unreplaced placeholders: {{variable}}, {variable} ✓
- No HTML or Markdown tags ✓
- No sensitive data (customer_id, full email, payment info) in body ✓
- JSON schema valid ✓

If any of these failed, they are already flagged as CRITICAL issues.
Your job is to evaluate the subjective aspects above.

=== SEVERITY LEVELS ===

CRITICAL: (Python pre-checks caught these — escalate to human review)
- Sensitive data exposure (customer_id, email, full payment details)
- Phishing/scam indicators ("verify password", "confirm identity", etc.)
- Medical/legal claims ("cures diabetes", "guaranteed results", etc.)
- Materially false business claims (e.g., promising non-existent feature)

[Note: If Python validation found CRITICAL issues, you should not reach evaluation —
 these are caught before LLM. Focus on subjective issues below.]

MODERATE: (Should improve)
- Personalization feels weak or generic (despite using names)
- Tone is slightly off (too corporate, too casual, too promotional)
- CTA is unclear or missing
- Missing context about what customer will receive
- Length significantly off (too verbose or too brief)

MINOR: (Optional improvements)
- Small wording tweaks for better flow
- One-off phrasing that could be more natural
- Non-critical style suggestions

PASS: (All good)
- Tone is warm and authentic
- Personalization is natural and effective
- Clear message with obvious next steps
- Appropriate length and content
- Ready to send

=== OUTPUT FORMAT ===

Return ONLY a JSON object with no additional text:

{
  "is_valid": true/false,
  "severity": "CRITICAL" | "MODERATE" | "MINOR" | "PASS",
  "issues": [
    "issue 1 (be specific and actionable)",
    "issue 2"
  ],
  "recommendation": "SEND" | "REFINE" | "MANUAL_REVIEW",
  "reasoning": "Clear explanation of your evaluation and recommendation"
}

Rules:
- is_valid: true only if severity is PASS or MINOR
- severity: match to most severe issue found
- issues: empty list if severity is PASS
- recommendation: SEND if PASS/MINOR, REFINE if MODERATE, MANUAL_REVIEW if CRITICAL
- reasoning: 2-3 sentences explaining why and what should happen next

Customer Context: preferred_name="Sarah", first_name="Sarah", plan_name="Premium"

Subject: "Welcome to Smoothie, Sarah!"

Output:
{
